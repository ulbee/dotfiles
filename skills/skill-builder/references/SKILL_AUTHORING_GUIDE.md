# Руководство по созданию скиллов для SkillStore

Как писать скиллы, которые корректно устанавливаются на любом AI-агенте (Claude Code, Cursor, Codex и др.).

## Быстрый старт: рабочий скилл за 5 минут

```bash
# 1. Создай структуру
mkdir -p ~/.claude/skills/my-skill

# 2. Напиши SKILL.md
cat > ~/.claude/skills/my-skill/SKILL.md << 'EOF'
---
name: my-skill
description: >
  [ЧТО ДЕЛАЕТ]. Используй этот скилл когда пользователь [ТРИГГЕРЫ].
  Триггерится на: "фраза1", "фраза2", "фраза3".
---

# My Skill

[Краткое описание цели]

## Шаги

1. [Шаг 1]
2. [Шаг 2]
3. [Шаг 3]

## Формат вывода

[Опиши ожидаемый результат]
EOF

# 3. Проверь
ls ~/.claude/skills/my-skill/
```

Задай тестовый запрос агенту и убедись, что скилл активировался.

---

## 3-уровневая система загрузки скиллов

Система загружает скиллы в три уровня:

1. **Метаданные** (`name` + `description`) — ВСЕГДА в контексте агента, ~100 слов максимум
2. **Тело SKILL.md** — загружается при срабатывании скилла, идеально < 500 строк
3. **Ресурсы** (`scripts/`, `references/`) — загружаются по необходимости, без ограничений

Это означает:
- `description` должен быть компактным, но максимально точным для триггеринга
- Тело SKILL.md — рабочие инструкции, не энциклопедия
- Тяжёлая документация → в `references/`

## Структура скилла

Минимальный скилл — директория с двумя обязательными файлами:

```
my-skill/
├── SKILL.md              # Описание + инструкции (обязательно)
└── scripts/
    └── my_tool.py        # CLI-инструмент (если есть)
```

Полная структура:

```
my-skill/
├── SKILL.md              # Описание + инструкции (обязательно)
├── scripts/              # Исполняемые скрипты
│   └── my_tool.py
├── references/           # Документация для загрузки в контекст
│   └── api_docs.md
└── assets/               # Шаблоны, изображения, файлы для вывода
    └── template.html
```

## SKILL.md — формат файла

### YAML-метаданные (обязательно)

```yaml
---
name: my-skill
description: >
  Краткое описание что делает скилл и когда его использовать.
  Триггерится на: "ключевые фразы", "по которым", "агент найдёт этот скилл".
---
```

**Правила для `name`:**
- Только латиница, цифры, дефисы: `my-skill`, `tracker-tool`
- Совпадает с именем директории

**Правила для `description`:**
- Конкретные триггер-фразы, по которым агент активирует скилл
- Не абстрактные описания, а точные слова пользователя
- Двуязычные триггеры (рус + англ) если аудитория смешанная
- Делай description "настойчивым": `"Используй этот скилл всегда когда..."` лучше пассивного описания
- Включай **что делает** И **когда использовать** в одном поле
- Не дублируй `when_to_use` в теле — всё триггерное идёт в `description`

**Плохой description:**
```yaml
description: Помогает с коммитами.
```

**Хороший description:**
```yaml
description: >
  Создаёт git-коммиты по Conventional Commits (feat/fix/chore/...).
  Используй этот скилл когда пользователь просит сделать коммит, упоминает
  git commit, хочет описать изменения, или говорит "закоммить это".
  Триггерится на: "коммит", "commit", "закоммить", "git commit".
```

### Тело SKILL.md

Всё после `---` — инструкции для агента в формате Markdown.

## Обязательная секция: Installation

**Это главная причина, почему скиллы не устанавливаются.**
Без этой секции агент не знает куда копировать файлы.

Вставьте эту секцию сразу после заголовка, **перед** основной документацией:

```markdown
## Installation

Этот скилл — директория с файлами SKILL.md + scripts/.
Для установки скопируй всю директорию в нужное место.

### Определи куда ставить

Проверь какие директории существуют на машине пользователя:

| Агент | Проверь существование | Куда ставить |
|-------|----------------------|-------------|
| **Claude Code** | `~/.claude/skills/` | `~/.claude/skills/<skill-name>/` |
| **Cursor** | `~/.cursor/skills/` | `~/.cursor/skills/<skill-name>/` |
| **Codex** | `~/.codex/` или `~/.agents/` | `~/.agents/skills/<skill-name>/` |
| **Другой агент** | ничего из вышеперечисленного | `~/.ai-skills/<skill-name>/` |

### Шаги установки

1. Определи агента (проверь какие директории из таблицы выше существуют)
2. Скопируй директорию `<skill-name>/` (содержащую этот SKILL.md + ресурсы) в путь из таблицы
3. Проверь: `python3 <путь_установки>/scripts/<tool>.py --help` (или другая команда верификации)

### ВАЖНО: НЕ использовать

- `claude plugin install` — это другой механизм, скилл так НЕ ставится
- Не нужно создавать `plugin.json`, `package.json` или любые конфиг-файлы
- Установка = просто копирование директории в правильное место
```

**Замените** `<skill-name>` и `<tool>` на реальные значения вашего скилла.

## Шаблон минимального скилла

```yaml
---
name: my-awesome-tool
description: >
  Описание инструмента. Работает через Python CLI.
  Триггерится на: "my tool", "мой инструмент", "запусти my-awesome".
---

# My Awesome Tool

Описание что делает скилл.

## Installation

Этот скилл — директория с файлами SKILL.md + scripts/.
Для установки скопируй всю директорию в нужное место.

### Определи куда ставить

Проверь какие директории существуют на машине пользователя:

| Агент | Проверь существование | Куда ставить |
|-------|----------------------|-------------|
| **Claude Code** | `~/.claude/skills/` | `~/.claude/skills/my-awesome-tool/` |
| **Cursor** | `~/.cursor/skills/` | `~/.cursor/skills/my-awesome-tool/` |
| **Codex** | `~/.codex/` или `~/.agents/` | `~/.agents/skills/my-awesome-tool/` |
| **Другой агент** | ничего | `~/.ai-skills/my-awesome-tool/` |

### Шаги

1. Определи агента (проверь директории из таблицы)
2. Скопируй директорию `my-awesome-tool/` в путь из таблицы

### ВАЖНО: НЕ использовать

## Использование

... (основная документация скилла)
```

## Чеклист перед загрузкой в SkillStore

### Структура
- [ ] Директория названа по `name` из YAML (латиница, дефисы)
- [ ] `SKILL.md` есть в корне директории
- [ ] YAML-метаданные содержат `name` и `description`
- [ ] Секция `## Installation` присутствует в SKILL.md
- [ ] Таблица путей для разных агентов заполнена (с реальным именем скилла)
- [ ] Секция "НЕ использовать" предупреждает о `claude plugin install`

### Скрипты
- [ ] Скрипты в `scripts/` — stdlib-only Python (без внешних зависимостей) или Bash
- [ ] Скрипты работают на macOS и Linux
- [ ] Указана команда верификации (ListTools, --help, и т.д.)
- [ ] Скрипты имеют `#!/usr/bin/env python3` шебанг

### Документация
- [ ] Описание содержит конкретные триггер-фразы
- [ ] Есть примеры вызова команд
- [ ] Описаны preconditions (env-переменные, токены)

### Токены и авторизация
- [ ] Если скилл требует токен — используй шаблон из `docs/template_token_auth.py`
- [ ] Токен НИКОГДА не хардкодится в SKILL.md
- [ ] `SERVICE_NAME` имеет префикс `skill_store_`

## Тестирование скилла

### Ручное тестирование триггеров

Сформулируй 2-3 реалистичных запроса, которые реальный пользователь мог бы написать:

```
# Хорошие тестовые запросы (конкретные, как пишет реальный человек):
"сделай коммит с описанием изменений в auth модуле"
"commit these changes, it's a bugfix for the login form"
"хочу закоммитить всё что в staging"

# Плохие (слишком абстрактные — пользователь так не пишет):
"сделай коммит"
"commit"
```

Для каждого запроса проверь:
1. Скилл активировался (агент прочитал SKILL.md)?
2. Вывод соответствует ожиданиям?
3. Агент не сделал ничего лишнего?

### Тест описания (triggering)

Если скилл не срабатывает на правильные запросы:
1. Добавь в `description` конкретные фразы, которые пишет пользователь
2. Сделай description более явным: `"Активируй этот скилл всегда когда..."`
3. Проверь что `name` совпадает с именем директории

---

## Частые ошибки

| Ошибка | Почему проблема | Решение |
|--------|----------------|---------|
| Пустой `description` | Скилл никогда не сработает | Добавь конкретное описание с триггерами |
| `name` не совпадает с именем папки | Конфликт при загрузке | Синхронизируй имена |
| SKILL.md > 500 строк | Слишком много токенов в контексте | Вынеси детали в `references/` |
| Все инструкции через MUST/ALWAYS | Хрупкие инструкции ломаются на edge cases | Объясняй причину, а не только правило |
| Нет примеров входа/выхода | Агент угадывает формат | Добавь раздел с примером |
| `description` только описывает, не триггерит | Скилл undertriggers | Добавь `"Используй этот скилл когда..."` |
| Нет секции Installation | Агент не знает куда ставить | Добавь шаблон Installation |

## Паттерны написания

### Определение формата вывода

```markdown
## Формат результата

ВСЕГДА используй этот шаблон:
# [Заголовок]
## Резюме
## Ключевые находки
## Рекомендации
```

### Примеры входа/выхода

```markdown
## Формат коммит-сообщения

**Пример:**
Входные данные: добавил JWT авторизацию
Результат: feat(auth): implement JWT-based authentication
```

### Ссылки на ресурсы

```markdown
## Использование

Если нужна детальная документация — прочитай `references/api-docs.md`.
Для генерации файлов используй скрипт `scripts/generate.py`.
```

## Антипаттерны — чего НЕ делать

### 1. Нет секции Installation

```markdown
# My Skill
Скилл для работы с API.
## Использование
python3 scripts/tool.py ListTools
```

**Проблема:** Агент не знает куда класть файлы → начнёт угадывать → `claude plugin install` → цикл ошибок.

**Решение:** Добавить секцию Installation с таблицей путей.

### 2. Захардкоженные абсолютные пути

```markdown
## Запуск
python3 /Users/john/.claude/skills/my-skill/scripts/tool.py
```

**Проблема:** Работает только у одного пользователя.

**Решение:** Использовать относительные пути `scripts/tool.py`. Агент сам разрешит полный путь относительно расположения SKILL.md.

### 3. Внешние зависимости без requirements.txt

```python
import requests  # не входит в stdlib!
```

**Проблема:** Скрипт упадёт если `requests` не установлен.

**Решение:** Использовать `urllib.request` из stdlib, или добавить `requirements.txt` и шаг установки зависимостей в Installation.

### 4. Shell-скрипт ссылается на соседний файл, которого нет в архиве

```bash
# В arcanum-cli.sh:
SANDBOX_CLI="$(dirname "$0")/sandbox-cli.sh"
"$SANDBOX_CLI" errors "$@"  # ← sandbox-cli.sh не в архиве!
```

**Проблема:** Скилл работает только в полном окружении автора. После загрузки в SkillStore и установки у другого пользователя — команды падают с "No such file or directory".

**Как обнаружить:**
- Искать в shell-скриптах: `$(dirname "$0")/`, `source`, `. ./`, `SCRIPT_DIR`, относительные пути к `.sh`, `.py`
- Искать в Python: `os.path.join(SCRIPT_DIR, "другой_скрипт")`, `subprocess.run(["bash", "./..."])`
- Для каждой найденной ссылки — проверить что файл есть в дереве скилла

**Решение:** Все файлы, на которые ссылаются скрипты, ДОЛЖНЫ быть включены в архив скилла. Перед загрузкой выполнить dry-run: скопировать скилл в `/tmp/test/`, запустить `ListTools` или `--help`.

### 5. Скрипт зависит от внешнего CLI-инструмента без документации

```bash
# В monium-cli.sh:
GRPCURL="ya tool grpcurl"   # ← а если ya tool не установлен?
```

**Проблема:** Скилл молча падает у пользователей без нужного toolchain.

**Решение:** В SKILL.md секции Installation указать **все** внешние зависимости:
```markdown
Требуется: `ya tool grpcurl` (Arcadia toolchain).
```

### 6. Только один агент

```markdown
## Installation
Скопируй в ~/.claude/skills/my-skill/
```

**Проблема:** Не работает для Cursor, Codex и других агентов.

**Решение:** Таблица путей для всех агентов (см. шаблон выше).

## Как загрузить скилл в SkillStore

```bash
# 1. Подготовь директорию скилла
my-skill/
├── SKILL.md
└── scripts/
    └── my_tool.py

# 2. Загрузи через CLI
python3 skillstore_tool.py CreateSkill --params '{
  "path": "/path/to/my-skill",
  "name": "My Awesome Tool",
  "description": "Описание для каталога",
  "author_name": "your-login",
  "tags": ["cli", "tool"]
}'

# 3. Проверь
python3 skillstore_tool.py GetSkill --params '{"slug":"my-awesome-tool"}'
```

## Обновление скилла

При обновлении SKILL.md или скриптов — создай новую версию:

```bash
python3 skillstore_tool.py CreateVersion --params '{
  "slug": "my-awesome-tool",
  "path": "/path/to/my-skill",
  "uploaded_by": "your-login",
  "changelog": "Описание изменений"
}'
```

## Рекомендуемый размер SKILL.md

| Секция | Объём |
|--------|-------|
| YAML-метаданные | ~100 слов |
| Installation | ~200 слов (шаблонная) |
| Основная документация | 1500-2000 слов |
| **Итого SKILL.md** | **< 3000 слов** |

Если документация превышает 3000 слов — вынеси детали в `references/`:

```
my-skill/
├── SKILL.md                  # Краткая сводка + Installation
└── references/
    ├── api_reference.md      # Полный API
    └── advanced_usage.md     # Продвинутые сценарии
```

## Тестирование перед загрузкой

### 1. Проверь что скрипт работает

```bash
python3 scripts/my_tool.py --help
# или
python3 scripts/my_tool.py ListTools
```

### 2. Проверь YAML-метаданные

```bash
head -10 SKILL.md
# Должен начинаться с --- и содержать name: и description:
```

### 3. Проверь Installation секцию

```bash
grep -c "## Installation" SKILL.md
# Должен вернуть 1
```

### 4. Имитируй установку

```bash
# Создай временную директорию как будто это чистая машина
mkdir -p /tmp/test-claude-skills/
cp -r my-skill/ /tmp/test-claude-skills/my-skill/
python3 /tmp/test-claude-skills/my-skill/scripts/my_tool.py --help
```
