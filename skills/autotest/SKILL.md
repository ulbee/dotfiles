Оркестрирует написание e2e-теста по TMS-кейсу. Работать в проекте LMS
(`/Users/yusokolova/arcadia4/hrtech/frontend/services/lms`). Полный справочник конвенций —
в [references/conventions.md](references/conventions.md), читай его перед генерацией spec.

## Вызов

`/autotest <tms-id> [--project lm] [--course <slug>] [--file <путь к spec>]`

- `<tms-id>` — номер кейса TMS (обязателен).
- `--project` — проект TMS (по умолчанию `lm`).
- `--course <slug[,slug2,…]>` — slug(-и) **уже существующих** курсов через запятую (кейс может
  требовать несколько). Если задан — тест пишется на них (в переданном порядке), курсы из
  предусловий НЕ создаются (шаг 2 пропускается целиком).
- `--file` — куда добавить тест. Если файл существует → добавить новый `test()` в конец,
  переиспользуя импорты/POM. Если нет → создать. Если не задан → предложить путь по разделу
  (`tests/playwright/tests/participantsInterface/<раздел>/<Название>.spec.ts`) и подтвердить.

## Процесс (выполняй по шагам)

0. **Если задан только `<tms-id>` и НИ ОДНОЙ опции** (`--project`/`--course`/`--file`) — сначала
   задай пользователю вопросы по каждой опции (инструментом AskUserQuestion), и только потом продолжай:
   - **Проект TMS** — по умолчанию `lm`.
   - **Курсы** — создать из предусловий кейса ИЛИ использовать существующие (тогда спроси slug(-и)
     через запятую). Прочитай кейс (шаг 1) до этого вопроса, чтобы показать, сколько курсов он требует.
   - **Целевой файл** — куда писать тест: существующий spec (укажи путь) или новый (предложи путь
     по разделу кейса и подтверди).
   Если хотя бы одна опция передана — вопросы не задавай, используй переданное + дефолты.

1. **Прочитать кейс.** Вызови `~/.claude/skills/tms/scripts/tms-cli.sh get <id> --project <project>`.
   Разбери: название, предусловия, шаги (Action → Expected).

2. **Предусловия → данные.** Кейс может требовать **один или несколько** курсов.
   - **Если задан `--course <slug[,slug2,…]>`** — пропусти этот шаг целиком: используй переданные
     курсы (в переданном порядке), ничего не создавай.
   - **Иначе** определи из предусловий, сколько курсов нужно и какие («Наличие опубликованного МЯ курса
     с языками RU, EN…»; кейс 887 — два курса: RU/EN и AB/DE). Для КАЖДОГО курса:
     - собери параметры (языки+порядок, публикация, число модулей);
     - создай скиллом `create-course`: сначала dry-run, покажи план, затем `--apply`. Если курсов
       несколько — вызывай с `--count 1`, `--count 2`, … (slug выйдет `slug_tmslv<id>_<count>`);
       один курс — без `--count` (slug `slug_tmslv<id>`);
     - если подходящий курс уже существует — переиспользуй, не плоди дубли.
   - Собери итоговый список slug'ов (один или несколько) — он пойдёт в тест.
   Если тест не требует спец-данных — пропусти шаг.

3. **Определить раздел и страницу.** По функциональности кейса выбери раздел UI и page-object
   (`courseCard` → `CoursePage`, `catalog` → `CatalogPage`, `trainings` → …). Путь spec — по разделу.

4. **Найти локаторы.** Переиспользуй существующие page-objects раздела. Если нужен новый элемент —
   найди `data-testid` в `src/client/screens/<Раздел>/` (grep `data-testid=`) и добавь локатор в POM
   (минимально, в стиле соседних). Приоритет: `getByTestId` → `getByRole` → `.locator('#id/.class')`.

5. **Сгенерировать spec** строго по конвенциям (см. references/conventions.md):
   - импорт `{ expect, test }` из `@playwright/test` (или из `../../fixtures`, если нужны
     `adminApiClient`/`trainingsCheckMock`);
   - `test('[Раздел]: <краткое название сценария>', annotations('https://tms.yandex-team.ru/projects/<project>/testcases/<id>'), async ({ page }) => {…})`
     — `annotations` из `tests/playwright/utils/annotations.ts` (обязательно, для TMS-sync);
   - **каждый Action кейса → отдельный `test.step('<Action дословно>', …)`** (заголовок = только действие,
     дословно — по нему синкается TMS); внутри — `expect(locator, '<Expected как описание>')…`;
   - курс через POM: `new CoursePage(page, slug)`, язык — `goto(lang)` или клик таба языка;
   - если создаются данные пользователя — идемпотентная чистка через `adminApiClient` в начале и `finally`.

6. **Разместить** тест в `--file` (добавить `test()` или создать файл). При создании — шапка импортов
   и POM как в соседних spec раздела.

7. **Проверить.** Прогони новый тест и покажи результат:
   `source ./tools/scripts/prepare-env-e2e.sh && pnpm run playwright test <file> -g "<заголовок>"`.
   Если упал по данным/локаторам — почини и перезапусти. Кратко отчитайся: путь файла, что создано
   (курс/тест), результат прогона.

## Принципы

- Заголовки `test.step` должны **дословно** повторять Action-шаги кейса (по ним идёт TMS-синк).
- Не выноси номер кейса в заголовок теста — он живёт в `annotations`.
- Не переусложняй: маленький POM-локатор лучше, чем `page.locator('.some-css')` без нужды.
- Сложные предположения (какой курс, куда файл, какой раздел) — подтверждай у пользователя, если неоднозначно.
