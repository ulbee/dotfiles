# Submit Changes Reference

## How arc submit works

`arc submit` combines branch creation, commit, push, and PR into one command.
It tracks state internally, so repeated calls update the same PR.

### First submit (from trunk)

```bash
arc checkout trunk
# make changes
arc submit -m "PR title and description"
```

What happens:
1. Creates a new branch (local: `pr-<id>`, remote: `users/<login>/<auto-generated>`)
2. Commits all tracked changed files (like `arc commit -a`)
3. Checks for conflicts with fresh trunk
4. Creates PR and publishes iteration

### Subsequent submits (from branch)

```bash
# make more changes
arc submit
```

No `-m` needed for updates. Commits changes and uploads new iteration to existing PR.

### Submit specific files

```bash
arc submit -m "PR title" path/to/file.go path/to/other.go
```

Without paths: all tracked files. With paths: only those files (including untracked).
With `--all`: include untracked files too.

## Conflict handling

`arc submit` handles conflicts differently from `arc rebase`:
- It **squashes all branch commits into one** before rebasing onto fresh trunk
- If conflicts are found, the working copy switches to fresh trunk with conflict markers

To resolve:
1. Edit conflicted files (check `arc status` for the list)
2. `arc add <resolved-files>`
3. `arc submit` again

To abort: `arc submit --abort` (returns to original state).

After conflict resolution the branch will contain a single squashed commit.
If you need to preserve commit structure, abort and use regular rebase:
```bash
arc submit --abort
arc commit -a -m "last changes"
arc pull trunk
arc rebase trunk
```

## Creating multiple PRs

### Independent PRs (--new)

Create a new PR from the same trunk point, leaving current PR unchanged:
```bash
arc checkout trunk
# edit a.cpp and b.cpp
arc submit -m "first PR" a.cpp
arc submit --new -m "second PR" b.cpp
```

Equivalent to checking out trunk and submitting again manually.

### Dependent PRs (--stack)

Create a PR that includes changes from current branch plus new changes:
```bash
arc submit -m "first PR" a.cpp
arc submit --stack -m "second PR" b.cpp
# second PR contains changes from both a.cpp and b.cpp
```

Useful for chains of dependent changes that should be reviewed and merged in order.

## Branch naming

- Local branch: `pr-<id>` (where id matches PR number)
- Remote branch: `users/<login>/<auto-generated-guid>`
- If you create a branch manually before submit, it keeps your branch name

## Navigation between submit branches

```bash
arc pr select    # TUI interface showing open PRs, select to switch (requires TTY)
arc checkout pr-<id>    # switch to specific submit branch by PR number
```

## Compatibility with arc pr create

`arc submit` works with PRs created via `arc pr create`, and vice versa:
```bash
# Create PR the traditional way
arc checkout -b my-feature trunk
arc commit -a -m "first commit"
arc pr create -m "my PR"

# Then update with submit
arc submit    # commits + pushes + updates the same PR
```

## Flags

| Flag | Effect |
|------|--------|
| `-m "desc"` | PR title/description (required for first submit) |
| `--new` | Create new independent PR |
| `--stack` | Create dependent PR including current branch changes |
| `--abort` | Abort conflict resolution, return to original state |
| `--all` | Include untracked files |
| `--merge` | Auto-merge after checks pass |
| `--auto` | Shortcut for `--merge --publish --no-code-review` |
| `--publish` | Publish iteration (default behavior) |
| `--publish=ci-success` | Publish only after CI passes |
| `--to <branch>` | Target branch (default: trunk) |
| `-r USER` | Add reviewer |
| `--label LABEL` | Add label |
| `-n` / `--no-verify` | Skip pre-commit hooks |
| `--skip-hook NAME` | Skip specific hook |
