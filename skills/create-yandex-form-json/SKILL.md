# Генератор JSON для Яндекс.Форм

Создаёт валидный JSON для импорта формы через UI Яндекс.Форм (https://forms.yandex-team.ru/ext/admin/ → Импортировать форму). Документация по импорту: https://docs.yandex-team.ru/forms/forms-settings?lang=ru#import

## Прежде чем начать

Полная JSON Schema находится в `references/schema/import_survey_schema.yaml`. Обращайся к ней за точными определениями полей, допустимыми значениями и граничными случаями. Этот SKILL.md — рабочий гайд, а схема — авторитетный источник.

## Входные форматы

Пользователь может описать форму в любом виде. Скилл должен принимать все перечисленные форматы:

- **Свободный текст** — описание вопросов и логики обычным языком в чате
- **Mermaid-диаграмма** — блок-схема ветвления в формате mermaid
- **ASCII-дерево** — древовидная структура вопросов текстом
- **Черновик JSON** — частично готовый или сломанный JSON для доработки/исправления
- **Таблица** — вопросы и варианты ответов в табличном виде

Если формат неоднозначен, уточни у пользователя логику ветвления перед генерацией.

## Типы задач

1. **Любой формат → JSON**: принять описание формы в любом из входных форматов, преобразовать в валидный JSON
2. **Отладка черновика JSON**: проверить по правилам этого скилла, особенно логику операторов в условиях
3. **Добавить интеграции**: настроить hooks (email, Трекер, Wiki, HTTP) на существующей форме
4. **Режим теста**: настроить баллы, правильные ответы, диапазоны результатов

## Структура документа верхнего уровня

```json
{
  "version": 2,
  "name": "Название формы",
  "questions": {
    "pages": [ { "items": [ /* вопросы */ ] } ]
  }
}
```

### Обязательные поля

| Поле      | Значение | Пояснение |
|-----------|----------|-----------|
| `version` | `2`      | Всегда ровно 2. Импорт отклоняет любое другое значение |

### Опциональные поля верхнего уровня

Полные определения — в `references/schema/import_survey_schema.yaml`. Основные:

| Поле | Тип | По умолчанию | Назначение |
|------|-----|-------------|------------|
| `name` | string | "Новая форма" | Заголовок формы |
| `allow_multiple_answers` | bool | `true` | Разрешить повторную отправку |
| `need_auth` | bool | `false` | Требовать авторизацию |
| `captcha` | `"std"│"ocr"│"nbg"│null` | `null` | Тип капчи |
| `texts` | object | i18n-дефолты | Тексты кнопок: отправить, назад, далее, заголовок, подзаголовок |
| `quiz` | object | — | Настройки тестового режима |
| `redirects` | array | — | Перенаправления после отправки (с условиями) |
| `hooks` | array | — | Группы интеграций |
| `conditions` | array | — | Условия показа кнопки «Отправить» |
| `styles` | object | — | Визуальная тема |

## Страницы

```json
"questions": {
  "pages": [
    {
      "items": [ /* вопросы */ ],
      "conditions": [ /* опционально: условия показа страницы */ ]
    }
  ]
}
```

- В многостраничных формах каждая страница отображается отдельным экраном с навигацией «Назад»/«Далее»
- У каждой страницы могут быть свои `conditions` — если не выполнены, страница пропускается
- Для простых форм достаточно одной страницы со всеми вопросами в `items`

## Объект вопроса

Базовая структура любого вопроса:

```json
{
  "id": null,
  "type": "enum",
  "label": "Текст вопроса",
  "slug": "q1_descriptive_name",
  "hidden": false,
  "comment": "Подсказка под вопросом",
  "placeholder": "Текст-заполнитель",
  "conditions": [],
  "validators": [],
  "image": null
}
```

### Основные поля

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `type` | **да** | Тип вопроса (см. ниже) |
| `label` | нет | Текст вопроса. По умолчанию: «Новый вопрос» |
| `slug` | нет | Уникальный идентификатор (латиница, цифры, `-`, `_`). Генерируется автоматически, но **всегда задавай явно** для читаемости и стабильных ссылок в условиях |
| `id` | нет | `null` для новых вопросов (сервер назначит сам) |
| `hidden` | нет | `false`. Скрытые вопросы не отображаются, но работают в условиях и интеграциях |
| `comment` | нет | Подсказка под заголовком вопроса |
| `placeholder` | нет | Текст-заполнитель внутри поля ввода |
| `conditions` | нет | Условия отображения вопроса (см. раздел «Условия») |
| `validators` | нет | Правила валидации (см. раздел «Валидаторы») |
| `image` | нет | Картинка из Яндекс Аватарницы |

## Типы вопросов

### `"string"` — текстовое поле

```json
{ "type": "string", "multiline": false }
```

| Поле | По умолчанию | Пояснение |
|------|-------------|-----------|
| `multiline` | `false` | `true` → textarea, `false` → однострочное поле |
| `initial` | — | Предзаполненное значение |
| `hint_source` | — | Источник автоподсказок |

### `"enum"` — выбор (Radio / Checkbox / Dropdown / Stars / Onerow)

```json
{
  "type": "enum",
  "widget": "radio",
  "items": [
    { "id": null, "slug": "option_a", "label": "Вариант A", "hidden": false },
    { "id": null, "slug": "option_b", "label": "Вариант B", "hidden": false }
  ],
  "modify_choices": "natural"
}
```

| Поле | Значения | Пояснение |
|------|----------|-----------|
| `widget` | `"radio"` (по умолчанию), `"checkbox"`, `"dropdown"`, `"stars"`, `"onerow"` | radio/dropdown/stars/onerow = один ответ; checkbox = несколько |
| `items` | массив Choice | Варианты ответов |
| `modify_choices` | `""│"natural"│"sort"│"shuffle"│null` | Порядок отображения вариантов |
| `show_first` | bool | Для dropdown: показывать первый элемент по умолчанию |
| `show_suggest` | bool | Показать поиск по вариантам |
| `initial` | массив slug-ов | Предвыбранные ответы |

**Объект варианта ответа (Choice):**
```json
{
  "id": null,
  "slug": "answer_slug",
  "label": "Текст ответа",
  "hidden": false,
  "image": null,
  "correct": null,
  "scores": null
}
```
`correct` и `scores` используются только в тестовом режиме (`has_quiz: true`).

### `"integer"` — числовое поле

```json
{ "type": "integer" }
```
Для ограничения диапазона используй валидаторы `min` / `max`.

### `"boolean"` — переключатель да/нет

```json
{ "type": "boolean" }
```

### `"date"` — выбор даты

```json
{ "type": "date" }
```
Валидаторы `min` / `max` принимают строки с датами.

### `"daterange"` — выбор диапазона дат

```json
{ "type": "daterange" }
```

### `"file"` — загрузка файлов

```json
{ "type": "file" }
```
Используй валидатор `count` (макс. количество файлов) и `size` (макс. размер в МБ, до 20).

### `"suggest"` — автоподсказка из источника данных

```json
{
  "type": "suggest",
  "data_source": {
    "name": "staff_login",
    "params": []
  },
  "multichoice": false
}
```
Доступные источники: `"country"`, `"city"`, `"staff_login"`, `"tracker_queue"`, `"dir_user"`, `"yt_table_source"`, `"wiki_table_source"` и др.

### `"matrix"` — оценка по шкале (строки × столбцы)

```json
{
  "type": "matrix",
  "rows": [
    { "id": null, "slug": "row_1", "label": "Критерий 1" }
  ],
  "columns": [
    { "id": null, "slug": "col_1", "label": "1" },
    { "id": null, "slug": "col_5", "label": "5" }
  ]
}
```

### `"comment"` — информационный блок (без ввода)

```json
{ "type": "comment", "label": "Информационный текст", "header": false }
```
`header: true` отображает текст как заголовок секции.

### `"payment"` — оплата через ЮMoney

```json
{ "type": "payment", "account_id": "41001234567890", "fixed": false }
```

### `"series"` — группа вопросов (контейнер)

```json
{
  "type": "series",
  "items": [ /* вложенные вопросы (любой тип кроме series) */ ]
}
```

## Условия (логика ветвления)

### ⚠️ Здесь возникает больше всего ошибок

```json
"conditions": [
  {
    "items": [
      {
        "operator": "and",
        "type": "question",
        "condition": "eq",
        "question": "q1_frequency",
        "value": "often"
      },
      {
        "operator": "or",
        "type": "question",
        "condition": "eq",
        "question": "q1_frequency",
        "value": "rarely"
      }
    ]
  }
]
```

### Структура

- `conditions` — массив **групп условий** (объектов Condition)
- Каждая группа содержит массив `items` из **элементарных условий** (ConditionItem)
- Несколько групп между собой объединяются через **ИЛИ**

### Поля ConditionItem

| Поле | Обязательно | Значения | Описание |
|------|-------------|----------|----------|
| `type` | **да** | `"question"`, `"language"`, `"origin"` | Что сравнивается |
| `condition` | **да** | `"eq"`, `"neq"`, `"lt"`, `"gt"` | Оператор сравнения |
| `operator` | нет | `"and"`, `"or"` | Как этот элемент связан с **предыдущим**. **По умолчанию: `"or"`** |
| `question` | для type=question | string | Slug вопроса-источника |
| `value` | нет | string (макс. 100 символов) | Значение для сравнения. Для enum → slug варианта ответа |

### Как работает поле `operator`

`operator` в каждом ConditionItem определяет, как он **связывается с предыдущим элементом** в той же группе:

```
item[0]: operator не имеет значения (нет предыдущего элемента)
item[1]: "or"  → item[0] ИЛИ item[1]
item[2]: "or"  → (item[0] ИЛИ item[1]) ИЛИ item[2]
item[1]: "and" → item[0] И item[1]
```

**По умолчанию в схеме — `"or"`**: если `operator` не указан, элементы связываются через ИЛИ. Это безопасно для типичного случая «показать, если выбран любой из вариантов». Тем не менее, **всегда указывай явно** во избежание двусмысленности.

### Типичная ошибка: случайное И вместо ИЛИ

Для **radio-вопросов** (взаимоисключающие ответы) `"and"` между вариантами создаёт невозможное условие — пользователь не может выбрать одновременно «Часто» И «Редко»:

```json
// ❌ НЕПРАВИЛЬНО — невозможное условие для radio
"items": [
  { "operator": "and", "type": "question", "condition": "eq", "question": "q1", "value": "often" },
  { "operator": "and", "type": "question", "condition": "eq", "question": "q1", "value": "rarely" }
]

// ✅ ПРАВИЛЬНО — показать при «often» ИЛИ «rarely»
"items": [
  { "operator": "and", "type": "question", "condition": "eq", "question": "q1", "value": "often" },
  { "operator": "or",  "type": "question", "condition": "eq", "question": "q1", "value": "rarely" }
]
```

### Шпаргалка

| Сценарий | Оператор между элементами |
|----------|--------------------------|
| Radio/dropdown: любой из ответов | `"or"` |
| Checkbox: ЛЮБОЙ из отмеченных | `"or"` |
| Checkbox: ВСЕ отмечены | `"and"` |
| Кросс-вопрос: Q1=X **и** Q2=Y | `"and"` |
| Кросс-вопрос: Q1=X **или** Q5=Y | `"or"` |
| Отрицание: Q1 ≠ "never" | используй `"condition": "neq"` |
| Числовое: Q1 > 5 | используй `"condition": "gt"` |

### Где используются условия

Синтаксис условий одинаков везде, где они встречаются:

- **Вопросы** (`question.conditions`) — показать/скрыть вопрос
- **Страницы** (`page.conditions`) — показать/пропустить всю страницу
- **Кнопка «Отправить»** (top-level `conditions`) — показать/скрыть кнопку
- **Редиректы** (`redirect.conditions`) — условное перенаправление
- **Группы интеграций** (`hook.conditions`) — условное срабатывание интеграции

## Валидаторы

```json
"validators": [
  { "type": "required" },
  { "type": "max", "value": 500 }
]
```

| Тип | Применим к | Нужен `value` | Описание |
|-----|-----------|---------------|----------|
| `required` | все | нет | Обязательное поле |
| `min` | string, integer, date, daterange, payment | да | Минимальное значение/длина/дата |
| `max` | string, integer, date, daterange, payment | да | Максимальное значение/длина/дата |
| `email` | string | нет | Должен быть email |
| `phone` | string | нет | Должен быть телефон |
| `url` | string | нет | Должен быть URL |
| `inn` | string | нет | Должен быть ИНН |
| `regexp` | string | да (регулярка) | Должен соответствовать паттерну |
| `decimal` | string | нет | Должен быть дробным числом |
| `russian` | string | нет | Только кириллица |
| `count` | file | да (int) | Макс. количество файлов |
| `size` | file | да (int ≤ 20) | Макс. размер файла в МБ |
| `single` | enum | нет | Ограничить checkbox одним выбором |
| `external` | все | нет | Валидация через `validator_url` формы |

## Тестовый режим (Quiz)

Превращает форму в тест с баллами. Кратко: добавь `has_quiz: true` на вопрос и `correct` / `scores` на варианты ответов. Объект `quiz` верхнего уровня настраивает отображение результатов.

```json
{
  "type": "enum", "widget": "radio", "has_quiz": true,
  "items": [
    { "slug": "paris", "label": "Париж", "correct": true, "scores": 10 },
    { "slug": "london", "label": "Лондон", "correct": false, "scores": 0 }
  ]
}
```

**Настройка результатов, тест для текстовых вопросов, полный пример** → `references/docs/quiz.md`

## Интеграции (Hooks)

Интеграции выполняются после отправки формы. Группируются в `hooks[]`, каждая группа содержит `subscriptions[]` и может иметь `conditions`.

8 типов: `email`, `tracker`, `wiki`, `jsonrpc`, `post`, `put`, `http`, `function`.

Все типы поддерживают `variables` для подстановки данных формы через `{variable_id}`.

```json
"hooks": [
  {
    "name": "Уведомление",
    "active": true,
    "conditions": [],
    "subscriptions": [
      { "type": "email", "email_to_address": "hr@company.com", "subject": "Новый ответ", "body": "..." }
    ]
  }
]
```

**Все типы интеграций, переменные, вложения, полные примеры** → `references/docs/hooks.md`

## Перенаправления (Redirects)

Перенаправление после отправки формы. Поддерживает условные редиректы (разные URL в зависимости от ответов) и переход на другую форму через `next_survey`.

```json
"redirects": [
  { "enabled": true, "url": "https://example.com/thanks", "button": "Перейти", "conditions": [] }
]
```

**Условные редиректы, GET-параметры с переменными, полные примеры** → `references/docs/redirects.md`

## Алгоритм: дерево ветвления → JSON

Когда пользователь даёт диаграмму ветвления:

```
Q1: Текст вопроса
├── A: Ответ 1 → Q2
├── A: Ответ 2 → Q2
└── A: Ответ 3 → Q3
```

1. **Выровнять** — все вопросы идут в плоский массив `items` (или по страницам)
2. **Назначить slug-и** — `q1_тема`, `q2_тема`. Slug-и ответов — описательные, в snake_case
3. **Собрать условия** — для каждого вопроса пройти вверх по дереву и найти ВСЕ ответы, которые его активируют
4. **Для multichoice-родителей** — включить slug каждого активирующего варианта, а не только одного
5. **Проверить операторы** — первый элемент `"and"` (условность), последующие `"or"` для альтернатив
6. **Не забыть «узловые» вопросы** — вопросы, доступные из нескольких веток, должны иметь условия, покрывающие все пути (например, Q6 доступен из веток Q3 и Q5)

## Чеклист перед отправкой

- [ ] Установлен `version: 2`
- [ ] Каждый `slug` уникален среди вопросов И вариантов ответов
- [ ] Slug-и содержат только `[a-zA-Z0-9_-]`
- [ ] В условиях `question` ссылается на существующий slug вопроса
- [ ] В условиях `value` ссылается на существующий slug варианта ответа
- [ ] Условия для radio/dropdown используют `"or"` между альтернативами (не `"and"`)
- [ ] «Узловые» вопросы (доступные из нескольких веток) содержат ВСЕ активирующие условия
- [ ] У вопросов с `has_quiz: true` заполнены `correct` и `scores` на вариантах
- [ ] Типы валидаторов соответствуют типу вопроса
- [ ] Для file-вопросов значение `size` ≤ 20
- [ ] Переменные (`variables`) в интеграциях определены до использования в шаблонах
- [ ] Для textarea-полей установлен `multiline: true`
- [ ] В многостраничных формах условия страниц не создают тупиков

## Автоматическая валидация по схеме

Ручной чеклист ловит логические ошибки (неправильные операторы, недостающие условия). Структурные ошибки (неверные типы полей, несуществующие свойства, пропущенные обязательные поля) нужно ловить автоматически, валидируя JSON по `references/schema/import_survey_schema.yaml`.

**Всегда валидируй сгенерированный JSON по схеме перед тем, как отдать пользователю.**

### Валидация через ajv-cli

```bash
npx ajv-cli validate -s references/schema/import_survey_schema.yaml -d survey.json --spec=draft7 --validate-formats=false --allow-union-types --all-errors
```

- `--validate-formats=false` — отключает проверку строковых форматов (`date-time` и др.), которые не встроены в ajv по умолчанию
- `--allow-union-types` — подавляет strict-mode предупреждения об union types (`type: [string, null]`) в схеме
- `--all-errors` — выводит все ошибки сразу, а не останавливается на первой
- ajv-cli поддерживает YAML-схемы нативно — конвертация не нужна

### Что ловит валидация, а что нет

**Схема ловит:** неверные типы (string вместо bool), несуществующие значения `type` (например, `"text"` вместо `"string"`), пропущенные обязательные поля (`type` на вопросах, `version` на верхнем уровне), невалидные enum-значения (например, `widget: "buttons"`).

**Схема НЕ ловит:** ошибки в логике операторов условий (И вместо ИЛИ), висячие ссылки на slug (условие ссылается на несуществующий вопрос), недостижимые вопросы из-за невозможных комбинаций условий, дублирование slug-ов. Для этого нужен ручной чеклист выше.

### Рекомендуемый порядок

1. Сгенерировать JSON
2. Прогнать валидацию по схеме → исправить структурные ошибки
3. Пройти ручной чеклист → исправить логические ошибки
4. Отдать пользователю
